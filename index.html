/ how I build

Five rules I picked up the hard way, shipping to real users.

The model interprets. The code decides.

Models are good at understanding how people talk and bad at math. So the model only fills in fields, and anything that has to be exact (numbers, dates, deletes) happens in code I can test.

Seen in Nutrigordo →

Every failure becomes a test.

When something breaks for a real user, that conversation becomes a test before the fix goes out. The same bug does not get a second chance.

Seen in Nutrigordo →

Everything has a ceiling.

An agent loop with no limit is a bill with no limit. Rounds, timeouts and paid calls all have a hard cap, and the caps have tests.

Seen in PrimeroLab →

Security lives in the database.

Access rules sit in the database, not in a check someone has to remember to write. Ask for another user's data and you get nothing back.

Seen in PrimeroLab →

One rule, one place.

Each rule is written once and everything else reads it. Two copies of the same rule drift apart, and you find out in production.

Seen in Composable CDP →
